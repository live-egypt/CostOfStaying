# ADR-001 — اختيار التكدس التقني
**الحالة: PROPOSED | التاريخ: 2026-10-31**

## السياق
المشروع لعبة 3D جماعية، Android أولاً، MVP لأربعة لاعبين، مع حاجة إلى Dedicated Server وسلطة خادم. لا يوجد كود إنتاجي قائم يفرض ترقية تدريجية.

## القرار المقترح
Unity 6.3 LTS + URP، C#، FishNet، Linux Dedicated Server. ابدأ دون Backend دائم حتى يثبت prototype الحاجة.

## البدائل
- Godot: أقل ارتباطاً بتكدس Unity، لكن يتطلب إعادة تقييم شبكة اللعبة والأدوات ومسار Android.
- Unity Netcode for GameObjects: بديل رسمي يحتاج مقارنة ميزات ومخاطر مع FishNet.
- Unreal: غير مبرر حالياً لمتطلبات MVP وحجم الفريق/المنتج غير المثبت.
- Native C++/Rust: لا يدخل إلا عند وجود profiler evidence.

## المبررات
تكدس واحد واضح، فصل منطق اللعبة عن المحرك، واستهداف خادم مستقل. الاختيار مقترح وليس اعتماداً نهائياً قبل prototype.

## المخاطر
توافق إصدارات FishNet/Unity، تكلفة الاستضافة، حجم العميل، الأداء على الأجهزة الضعيفة، واعتماد المشروع على طرف ثالث.

## التحقق
بناء Android وLinux، اختبار اتصال لاعبين على جهازين، اختبار دورة مباراة، profiling على جهاز منخفض، ومراجعة الإصدارات المثبتة.

## التراجع
إذا فشل prototype في متطلبات الأداء/الاستقرار أو ظهرت مشكلة توافق جوهرية، افتح ADR بديل مع أدلة مقارنة.
