# ثمن البقاء | The Cost of Staying

**حزمة التوثيق: v2.1 — حالة المشروع: Pre-production**

لعبة بقاء نفسي جماعية؛ كل ثانية تستنزف Vitality، ونقل المعاناة يؤخر الانهيار لكنه يضيف كلفة Betrayal، والموت ينقل اللاعب إلى دور Spirit.

## الحالة الحالية
- المنصة المستهدفة أولاً: Android.
- نطاق MVP: مباراة مكتملة لأربعة لاعبين وخريطة واحدة.
- حالة التنفيذ: لا يوجد كود لعبة أو Unity project أو Dedicated Server أو اختبارات منفذة.
- حالة قواعد اللعب: خط أساس PROPOSED FOR PLAYTEST، وليس اعتماداً نهائياً.
- حالة التكدس التقني: PROPOSED، باستثناء مبدأ سلطة الخادم المعتمد تصميمياً وغير المنفذ.
- قوالب الفحص في `.github/workflows` يدوية فقط وليست CI منفذاً.

## حفظ ونقل المشروع
- [حزمة النقل إلى مشروع ChatGPT جديد](docs/transfer/README.md) — لقطة الحالة، جرد GitHub، بصمات المصادر، الفجوات، وتعليمات الاستئناف. هذه الحزمة لا تستبدل تصدير محادثات ChatGPT الأصلية.

## نقطة البداية
ابدأ من [فهرس الوثائق](docs/README.md) و[حوكمة الوثائق](docs/governance/DOCUMENT_GOVERNANCE.md) و[سجل حل التعارض](docs/governance/CONFLICT_RESOLUTIONS.md)، ثم [ميثاق المشروع](docs/00_PROJECT_CHARTER.md) و[قواعد اللعبة](docs/02_GAME_RULES_SPECIFICATION.md).

## مبادئ العمل
1. لا قرار معماري مهم بلا ADR.
2. لا ادعاء أداء بلا قياس قابل للتكرار.
3. لا تغيير حالة حساس بناءً على نتيجة يرسلها العميل.
4. اربط كل متطلب بضابط واختبار ودليل.
5. افصل المقترح والمعتمد والمنفذ والمتحقق منه.
6. أي وثيقة جديدة تدخل الكتالوج والفهرس في نفس الالتزام.
7. عند التعارض: ADR، ثم مواصفة القواعد، ثم وثيقة النظام.

## التكدس المقترح
Unity 6.3 LTS + URP، C#، FishNet، Linux Dedicated Server. يؤجل Backend الإنتاجي إلى ما بعد prototype. التفاصيل في ADR-001 وADR-003.

## دلالات الحالة
التعريف الملزم في [حوكمة الوثائق](docs/governance/DOCUMENT_GOVERNANCE.md).
- **PROPOSED:** مقترح لم يعتمد.
- **PROPOSED FOR PLAYTEST:** خط أساس مطلوب اختباره قبل الاعتماد.
- **APPROVED:** قرار معتمد تصميمياً.
- **IMPLEMENTED:** منفذ في كود محدد.
- **VERIFIED:** اجتاز اختباراً محدداً وله دليل محفوظ.
- **TBD:** لم يحسم بعد.

وجود وثيقة لا يعني أن النظام نُفذ أو اختُبر.
